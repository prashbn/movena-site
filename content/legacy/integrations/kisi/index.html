Movena + Kisi

Movena is the operating platform for modern fitness businesses — from boutique Pilates and yoga studios to CrossFit boxes, boxing and martial arts facilities, independent gyms and multi-location operators. With Kisi, that experience extends all the way to the front door: eligible, enrolled members receive the right access automatically as their memberships and bookings change, while Kisi continues to manage the physical doors, hardware and access infrastructure.

What the integration does

  • Memberships open doors. Enable facility access on a plan and members with an eligible active membership receive access without requiring a booking — no fobs to hand out, no lists to maintain.
  • Bookings open doors too. An eligible booking independently creates time-bounded access for that session, so class-based plans work naturally without around-the-clock entry.
  • Changes take care of themselves. Membership cancellations and expiries remove access when the entitlement ends; an explicit suspension prevents access until it's lifted; reactivation brings access back.
  • Multi-location by design. Each participating location maps to its own Kisi Place and member Group, and the same Kisi user supports access across every location in the organisation — no duplicate seats.

Who decides what

Movena determines which enrolled members should receive access and, where applicable, the time window for booking-based access. Kisi manages and enforces the physical environment — doors, hardware, opening schedules and other Kisi-configured restrictions. Physical door entry never depends on a real-time request to Movena.

Two controls, both in Movena, decide participation: Include facility access on the membership plan, and enrolment on the member. Enrolment is a participation gate — an eligible membership or booking alone never automatically enrols a member or creates a Kisi user.

Setting it up

  1. Ask Movena to activate the Access Control add-on for your participating locations.
  2. In Movena, go to Settings → Access Control, select Connect, choose Kisi, and enter an API key created by your Kisi organisation owner or administrator (Kisi recommends the owner's account, so the key survives admin changes). Movena verifies the credential with Kisi before saving it; it's stored encrypted and never displayed again.
  3. Select Configure Access Control. For each location, Movena creates the Kisi Place and member Group the integration needs and configures live event updates — there are no Kisi resource IDs to copy into Movena.
  4. In the Kisi console, configure the location's controller, reader and doors, and add the doors members should reach to the group Movena created — Movena Members — [location name]. Doors and hardware stay managed in Kisi; Movena never modifies them.
  5. When the location is ready, select Turn on in Movena. Before you confirm, Movena shows the expected member impact and the estimated Kisi user capacity required.

What you need

  • Kisi organisation owner or administrator rights, an active Kisi subscription with sufficient user capacity, and installed Kisi hardware.
  • The Movena Access Control add-on, enabled for your participating locations.
  • A Movena account with Owner or Manager access to the gym's settings.

Built to be trusted with your doors

  • Continuous reconciliation. Movena processes access changes asynchronously, consumes Kisi's events as they arrive, and periodically reconciles Movena-managed access with Kisi so failed operations or drift are detected and retried.
  • Movena only manages Movena-owned access. It modifies or removes only access it can identify as Movena-managed; existing manual or independently managed Kisi access is left untouched.
  • No duplicate Kisi users. Users are created only when first required; where an existing user in your organisation can be safely matched by email, Movena reuses that user.
  • Capacity checked first. Operations that may provision many users — enabling a location, adding facility access to a sold plan — check available Kisi capacity up front; a known shortfall means the operation is refused, never half-applied.
  • Credentials protected. Your API key is verified, encrypted at rest and never shown again; event updates from Kisi are individually signed and verified.

Ending the integration

Use the cancellation workflow in Movena first — it revokes Movena-managed access and decommissions the integration in an orderly sequence while Movena still has access to the Kisi organisation. Disconnect the API credential only after that completes; disconnecting alone just removes Movena's ability to talk to Kisi and isn't a substitute for cancelling Access Control.
